  • 护栏是图节点，不是提示词请求：订单号必须来自用户文本（32 位 hex 校验），伪造参数被类型化拒绝并可恢复；写操作强制升级人工审核（HITL 工作台）。
  • 工具治理：三态结果（成功/失败/未知，未知不得产生肯定性回复）、幂等键 + UNIQUE 约束（重放返回原工单）。
  • 评测抓到真 bug：图级轨迹断言发现 validate 节点导致工具调用被执行两次——幂等键使其无害化，修复后留下回归任务（复盘 →）。
  • 可观测：每轮对话落盘 run 级 JSON 轨迹（节点/时延/token），PII 脱敏后才入库与出境。
  • 存储选型有论证：当前规模先本地实现（BM25+numpy），向量库留迁移接口与对比评测（ADR →）。

一句话追问我的回答锚点
为什么不用豆包直接解决？查不了自有订单库、写不了工单、保证不了金额与系统一致、控不了权限——工具调用+数据一致性+分级审批是 Agent 的定义性场景（τ²-bench 同款）
为什么 LangChain/LangGraph 而不是自研？框架选型对比有出处（ADR-0001），同时保留 120 行手写 ReAct 循环作为理解参考实现——被问底层机制时从裸 API 讲起
评测怎么做的？轨迹断言 + 消融对比 + 金标动态定位（条款正则），全部可复现、零虚数
